# 2026-08-28 Windows GPU追従の再発修正

## 再発原因

- 2026-08-27 23:52の停止について、同時刻以降のWindows Application Error / WER、Rust panic、アプリ内errorはなかった。
- アプリログでは23:52:11に録音を開始し、モデルが`gpu_device 1` / `Vulkan1`へロードされた。表示GPUはRTX 5070 Ti / device index 0だった。
- 23:52:47にGPU監視の「表示追従アプリを同期」があり、停止はクラッシュではなく監視による終了・再起動だった。
- 前回修正は`--device-index`付き起動には有効だったが、ショートカットや自動起動など引数なしの起動を事前補正していなかった。監視もモデルロード後のGPUカウンターを見るまで不一致を検出できなかった。

## 修正

- `deviceIndexByDisplayGpu`があるアプリは、GPUカウンターではなく長時間動く本体プロセスの`--device-index`を追従状態の正本にした。
- 正しいdevice indexが付いていれば、Windowsが別GPUの補助contextも報告しても再起動しない。
- 引数なし、または異なるdevice indexで起動した場合だけ、表示GPUに対応する引数付きで一度再起動する。
- CLIのsingle-instance転送で短時間だけ現れる補助プロセスは、起動3秒未満なら判定対象外にした。
- 監視間隔を5秒にし、起動引数の補正後はGPU contextの出現を待たず成功扱いにした。
