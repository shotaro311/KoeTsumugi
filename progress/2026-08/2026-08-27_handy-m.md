# 2026-08-27 Windows GPU追従時の不安定化調査と修正

## 目的

- Windows版KoeTsumugiのクラッシュと、音声入力が途中で閉じる現象の原因を特定して改善する。
- RTX 5070 Ti / RTX 5060 Tiの表示GPU追従が影響しているかを実機で確認する。

## 原因

- Windows Application Event Logで、2026-08-27 16:30:01に`koetsumugi.exe 1.0.5.0`が`vulkan-1.dll 1.4.350.0`、例外`0xc0000409`で異常終了した記録を確認した。
- KoeTsumugiの永続設定は`transcribe_gpu_device: 1`でRTX 5060 Tiを選択していた一方、表示GPUとWindowsの高パフォーマンス割当はRTX 5070 Tiだった。
- 既存の表示GPU追従はWindowsのプロセス描画GPUだけを変更し、音声モデルのVulkanデバイスを変更していなかった。録音でモデルがGPU 1へロードされると不一致判定され、監視が約30秒ごとにKoeTsumugiを再起動していた。
- 16:31:20から16:33:29まで約32秒間隔の再起動をアプリログで確認した。音声入力が突然閉じる直接原因はこの再起動ループだった。
- 監視プロセスの多重起動と、複数プロセスによるwatcher log競合も確認した。

## 修正

- 通常のデスクトップ起動でも`--device-index N`をruntime-onlyの音声モデルGPU指定として扱うようにした。永続設定や履歴、録音は変更しない。
- 表示GPU追従設定へRTX 5070 Ti=`0`、RTX 5060 Ti=`1`の対応を追加し、再起動時に対応する`--device-index`を渡すようにした。
- 同一の表示GPUとプロセスPID群に対する再起動を1回に制限し、GPU contextの観測遅延や失敗で再起動を繰り返さないようにした。
- named mutexでGPU監視を1プロセスに制限した。
